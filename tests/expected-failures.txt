# Tests known to fail, with the reason. tests/run.sh reports these as XFAIL
# and does not count them against the gate - but it *does* fail the run if one
# of them starts passing, so this list cannot quietly go stale.
#
# Format: <test name> <reason>
#
# Nothing here is "we did not get around to it and it happens to fail". Each
# entry is either a feature this core deliberately does not implement, or a
# test whose premise does not apply to it.

# Requires misaligned load/store to be handled *in hardware* - the test has no
# trap handler at all and expects `lh` at an odd address to just return the
# right value. The spec permits either that or a misaligned-address exception,
# and this core deliberately takes the exception route (added so that M-mode
# firmware can emulate misaligned accesses, which is how real RISC-V platforms
# handle them). rv32mi-p-{lh,lw,sh,sw}-misaligned and rv32mi-p-ma_addr cover
# the trapping behavior this core actually implements, and all pass.
rv32ui-p-ma_data  needs hardware misaligned data access; this core traps instead

# Needs the debug-spec trigger module (tselect/tdata1/tdata2) to set hardware
# breakpoints. That is part of the same feature family as the JTAG debug
# transport, which is not implemented either - see tests/README.md.
rv32mi-p-breakpoint  needs debug-spec triggers (tdata/tselect)
