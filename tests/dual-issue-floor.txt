# How much dual issue a test is required to contain, on the wide core.
#
#   <test-name>  <minimum slot-1 retirements>
#
# Read by both tests/run.sh and tests/cosim.py, so the number lives once.
#
# ---- why a floor exists at all ----
#
# A test written to exercise a mechanism will keep passing after it stops
# exercising it, and give no sign. Set `issue_pair = 1'b0` in
# rtl/ooo/core_ooo.v and vernier-p-pairing still reaches its own pass
# condition *and* still matches Spike instruction for instruction - because
# single-issuing that program is a correct execution of it. Nothing about the
# answer is wrong. The test has simply stopped being about dual issue, and
# would report PASS/MATCH forever.
#
# That is not hypothetical for this corpus. Co-simulation reported 82 of 82
# traces matching on the wide core while retiring 63 instructions in slot 1
# out of 28,262 - 0.22%, with 70 of those traces retiring none at all.
# docs/practices.md section 40.
#
# ---- choosing the number ----
#
# vernier-p-pairing retires 6,143 in slot 1 today, out of 30,804. The floor
# is set well below that because the quantity is microarchitectural - fetch
# buffer depth and issue policy both move it, legitimately - and what is
# being guarded against is a collapse to near zero, not drift. If a change
# takes this below the floor for a good reason, the number here is meant to
# be edited, with the reason in the commit message.
#
# Only enforced when CORE=ooo. cpu_core.v has no second slot, and on it the
# same test is expected to retire zero.
#
# ---- stage 1d: floor retired ----
#
# rtl/ooo/core_ooo.v was rewritten (register renaming + an 8-entry ROB
# doubling as its own age-ordered issue window, replacing the previous
# design's fixed-pair slot-0/slot-1 dispatch). Stage 1d dispatches and
# retires one instruction wide by design - "slot 1" is not a concept this
# core has, the same as cpu_core.v above, so vernier-p-pairing now retires 0
# in slot 1 unconditionally and the floor above would never again mean what
# this file says it means (a regression toward zero). This is not the
# collapse the floor exists to catch: the trace still matches Spike
# instruction for instruction, and the core still reorders - just not
# through a second dispatch slot. That evidence now comes from
# `ooo_alu_reorder_count`/`ooo_load_reorder_count` (sim/tb_top.v,
# sim/tb_bench.v), which count actual out-of-program-order issue directly
# and are not tied to any particular dispatch width.
#
# vernier-p-pairing itself is left in place unchanged - its trace matching
# Spike is still a real, useful check - only the slot-1 floor is retired.

vernier-p-pairing 0
